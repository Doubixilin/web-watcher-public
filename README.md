# Web Watcher

Web Watcher 是面向 macOS 的本地网站连通性、网络健康监测与网络恢复软件。它关注 Wi-Fi 断开，以及 Wi-Fi 仍连接但上游不可达等场景，帮助观察故障并按策略尝试可用网络。

目标是提供菜单栏入口和完整窗口，持续观察网站、DNS、代理与网络质量，保存故障证据，并在符合策略时恢复网络连接。

当前开发版为 0.3.0：在 Wi-Fi 详情、实时网速与趋势、候选管理和按需进程流量基础上，增加断线记录、自动恢复、手动连接与联网验证。自动恢复初始关闭，真实切网尚待实机验收；网站趋势仍保留在当前会话内。

## 开发版运行

本机需要 Xcode 或相应 Swift 开发工具，工程最低目标为 macOS 14；目前实际验证环境为 macOS 26.6.2、Swift 6.4。

```sh
./scripts/run-dev.sh
```

该脚本构建调试版，并在被忽略的 `.build/Development/` 内准备最小开发应用，方便 macOS 识别固定的应用身份与定位权限。它不是安装包或发布流程。启动后显示窗口和菜单栏的实时上下行速率，不依赖终端保持开启；目前没有后台组件或登录启动。

窗口提供总览、网站检测、Wi-Fi 与候选、恢复与记录、进程流量、显示设置。关闭窗口后监测和恢复继续；退出停止全部采样。暂停网站监测同时暂停自动恢复，实时网速与状态记录继续；进程采样在离开该页或关闭窗口后停止。

默认检测百度 DNS、腾讯 TCP 443、百度与腾讯 HTTPS HEAD。四项依次执行，单项超时 5 秒，每轮完成后等待 30 秒，不跟随 HTTP 重定向。HTTPS 预期状态为 200–399；4xx / 5xx 显示为“服务器可达、响应未达预期”。这些默认目标和频率是试运行起点。

```sh
swift test
swift run WebWatcher --probe-once
```

后一命令输出本机探测 JSON，包含连接环境，保存时放在 `.local/`，不要提交。`swift run WebWatcher --recovery-check` 只读检查无线状态和绑定 Wi-Fi 的 TCP 可达性，不切网。应用不读取或保存网站登录凭据、Wi-Fi 密码，不修改 DNS 或代理；连接入口和启用后的恢复策略会实际切换 Wi-Fi。

DNS 耗时可能来自系统缓存。连接建立时间可能包含 TLS / 代理握手；HTTP 时间为请求开始至响应首字节，探测总耗时另列。未知字段不会用其他耗时代替。当前没有 ICMP 探测，不能把这些结果称为丢包率。

系统代理、VPN 和隧道会影响路径。连接的本地地址、映射接口、对端和代理标记按系统提供的信息显示；本地接口可能是回环接口，对端可能是代理，不能据此宣称已经绕过代理或验证物理出口。Wi-Fi 名称受系统定位权限约束，只有点击“授权读取 Wi-Fi 名称”后才请求授权；没有授权或系统未提供名称时明确显示未知，不用候选名称代替实际 SSID。名称不可读不等于 Wi-Fi 断开。

## Wi-Fi、网速与进程

- Wi-Fi 详情来自 CoreWLAN：RSSI、噪声、信噪比、当前连接协议、频段、信道、信道宽度和链路发送速率。信号等级只是经验提示，与网站可达性分别展示。
- Wi-Fi 6 / 6E / 7 按当前连接协议和频段判断，不表示路由器或 Mac 的最高能力。协商速率用 Mbps，不能当作公网带宽测速。
- 实时速率来自所选物理接口的 64 位收发计数器，约每秒计算一次。自动选择排除回环与隧道，也可手动指定网卡。接口变化、计数器回退、休眠长间隔后重新建立基线；未知显示 `—`。
- 菜单栏可显示仅图标、下载、上传或上下行，显示设置自动保存在本机。
- 主、备用候选标记保存在本机，区分已保存与扫描来源；标记本身不切网，也不代表公网可用。“连接并验证”会真实切网；自动恢复开关位于“恢复与记录”。须先保存系统连接凭据，验证联网后再用于持续恢复。
- 进程页点击开启后，通过系统 `nettop` 读取进程累计收发，按连续有效样本的实际间隔计算速率；命令有 3 秒超时、输出上限和退出清理。采样间等待 3 秒，连续三次失败会暂停，可重新开启。代理和共享辅助进程的软件归属不猜测，进程数据不能和物理接口总量相加。本机实测出现多次超时，该项为试验性功能，尚未通过稳定性验收。

恢复事件保存在本机，保留最近 500 条，包含掉线、观测间隔、候选尝试及联网验证。掉线判断每 2 秒复核；仍关联时采用独立的短周期、多目标无线 TCP 证据，不使用单个网站或 HTTP 错误触发切换。策略、时长和验收限制详见 [会话交接](docs/HANDOFF.md)。当前不包括 ICMP 丢包、完整故障健康评分、网页完整历史、登录启动和主动公网测速。

## 项目方向

- 网站检测支持 HTTP、HTTPS、DNS、TCP，并区分直连与代理路径。
- 网络健康分别展示延迟、ICMP 丢包、抖动、请求失败率和 Wi-Fi 信息。
- 故障记录关联当时的网络与检测结果，帮助判断问题发生在哪一层。
- 网络恢复支持指定候选网络、手动切换、自动切换和结果验证。
- 配置与历史保存在本机，轻量检测常驻，完整测速按需运行。

M1 采用 Swift Package、SwiftUI 窗口与 AppKit 菜单栏，使用系统 DNS-SD、Network.framework、URLSession 和 SystemConfiguration，未引入第三方运行依赖或复制外部项目代码。

## 本地与远程

GitHub 公开仓库：[Doubixilin/web-watcher-public](https://github.com/Doubixilin/web-watcher-public)，默认分支为 `main`。公开历史从经过隐私检查的 0.3.0 源码快照开始。

本机网络名称、候选、偏好和恢复事件由应用保存在本机，仓库不包含预设的个人 Wi-Fi 名称。需要开发环境记录时，可放在被 Git 忽略的 `.local/environment.md`，其他机器自行建立。实际凭据、网络地址、抓包、数据库和原始日志不随源码发布；提交前仍需检查文件内容与将要推送的历史。

项目尚未选择对外发布许可证。调研项目的许可证不代表本项目已经采用相同许可证；复用代码时应记录来源、版本和许可证。
