# Web Watcher 架构建议

日期：2026 年 10 月 6 日

## 已确定与待验证

产品方向已经确定为 macOS 本机软件，具备界面、持续检测、历史与网络恢复能力。M1 已采用 Swift Package、SwiftUI 与 AppKit，原生构建及只读探测可运行。当前实现与验收边界统一记录在 [会话交接](HANDOFF.md)，本文件其余部分仍是后续架构建议。

M1 使用 DNS-SD 系统解析、Network.framework TCP、URLSession HTTPS 和 SystemConfiguration 网络快照，未引入第三方运行依赖。只提供系统默认路径，不承诺绕过代理或验证物理出口。DNS 可能命中系统缓存；URLSession 的连接建立时间可包含 TLS，缺失的阶段时间保持未知。

本轮阅读了 [Gatus 的协议客户端](https://github.com/TwiN/gatus/blob/master/client/client.go)、[MeOrThem 的 HTTP 探测](https://github.com/kanzie/meorthem/blob/main/Sources/MeOrThemCore/Monitoring/HTTPProber.swift) 与 [Stats 的应用入口](https://github.com/exelban/stats/blob/master/Stats/AppDelegate.swift)。只参考职责与语义，无源码复制；当前少量探测使用系统接口已足够，引入独立引擎尚无验证收益。URLSession 阶段与路径字段按 [Apple 指标接口](https://developer.apple.com/documentation/foundation/urlsessiontaskmetrics) 和本机 SDK 注释定义。

本轮观测扩展采用 CoreWLAN 与持有完整生命周期的 CLLocationManager；定位请求仅来自用户按钮。SSID 遵循 [Apple 的定位隐私要求](https://developer.apple.com/forums/thread/759044)，不读取受限文件或调用私有接口。调试运行使用固定身份的最小本地应用，正式分发仍待后续安排。

物理接口速率通过 Darwin 路由 `sysctl` 的 `NET_RT_IFLIST2` 取得 64 位计数器，并按单调时间差计算；自动选择只考虑有效的 Wi-Fi / Ethernet 接口。候选角色与显示偏好使用本机 UserDefaults，历史趋势暂在内存中保留。进程统计使用有超时和输出上限的 `nettop` 子进程，失败不阻塞主监测；停止、关闭窗口和退出时清理采样。数据采集思路参考 [Stats 的网络读取模块](https://github.com/exelban/stats/blob/master/Modules/Net/readers.swift)，未复制代码或引入运行依赖。

0.3.0 新增独立的 `RecoverySession`、纯状态 `RecoveryPolicy`、可替换连接适配与原子本地事件日志。系统事件结合短周期复核，不依赖网页长轮次触发。数字 IP TCP 连接要求无线接口，成功时核对实际本地地址的接口；默认网站检测仍可能经代理。实际系统连接使用受超时保护的 `networksetup`，不读取 / 传递密码或提权。已有模拟测试和只读无线路径证据；无弹窗后台连接、锁屏与断网恢复仍需实机验收。只有实测需要时才增加 helper，完整现状统一见 [会话交接](HANDOFF.md)。

## 软件组成

| 组成 | 职责 |
| --- | --- |
| 菜单栏与主窗口 | 显示总览、目标、健康趋势、事件历史和恢复状态 |
| 探测与调度 | 按目标运行 DNS、TCP、TLS、HTTP 或 ICMP 检测，限制并发与超时 |
| 诊断与策略 | 整理证据、给出状态与疑似原因，决定是否满足恢复条件 |
| 本地存储 | 保存配置、检测摘要、事件和网络环境；保留周期可配置 |
| macOS 网络适配 | 获取接口与 Wi-Fi 信息，执行被授权的候选网络连接，报告权限与结果 |

先评估单一应用进程：窗口关闭后，由菜单栏应用继续监测。若必须支持用户注销后恢复、特权操作或 UI 进程异常后的救援，再根据实测需要设计最小 helper。不能仅凭“后台”二字预先引入复杂进程结构。

同时需要准确说明边界：单一用户应用通常依赖用户会话；重启后的 FileVault 解锁阶段、系统休眠和物理断电不能被普通应用恢复承诺覆盖。

## 探测模型

每条探测记录至少关联目标、协议、配置的路径、实际可观察的接口、网络环境、时间、阶段结果、耗时和错误。分别保留网络可达性与目标业务条件，避免把 HTTP 错误归结为出口断网。

初期不承诺所有协议都能精准分解 DNS、TCP、TLS 与首字节时间。选择系统接口后，按其实际能够提供的阶段记录，未测得的字段保持未知。

路径需要区分系统默认、明确直连和指定代理。代理软件接管默认路由及合成 DNS 时，关闭 HTTP 代理选项并不一定等于绕过隧道；需要验证接口绑定、解析路径与实际连接来源。

设置国内基础连通性、国外服务、代理服务和关键远程服务等目标组。网站自己的 HTTP 规则可不同，但网络恢复只使用明确指定的基础与关键路径证据。

## 恢复状态

建议使用可观察的状态：正常、异常观察、切换候选、验证候选、冷却等待、所有候选不可用。保留人工暂停与取消入口。

- 连续多轮独立检测证据异常后，进入候选尝试。
- 连接请求完成后，等待有效网络配置，并重新探测；不能仅检查命令退出码或 IP 是否发生变化。
- 候选成功后进入冷却等待；失败时继续其他允许的候选，必要时重新尝试原网络。
- 全部失败时保存事件，退避后继续检测和尝试，不进入永久停止状态。
- 用户主动切网或修改设置时，避免立即被策略切回；具体交互在实现阶段确定。

Wi-Fi 连接命令、凭据访问、锁屏和登录启动需要在 macOS 26.6.2 上实测。无法在后台使用系统已有凭据时，应先解决系统允许的授权与凭据管理，再启用自动恢复；禁止把密码写入源码或日志。

## 开源复用

Gatus 是探测设计或独立引擎的候选，当前不能假设它有稳定的嵌入 API。引入 Go 子进程会增加打包和生命周期成本，需要与原生探测的收益比较。

MeOrThem 的逻辑与 AppKit 分离方式、Stats 的原生应用结构可以作为代码阅读起点。复用时固定来源版本、保留许可与归属信息，单独检查依赖和自带第三方二进制。

第一版建议使用本机存储，不预设云平台、插件系统、分布式监测或全流量抓包架构。数据保留周期与默认监测频率通过持续运行测量确定。
