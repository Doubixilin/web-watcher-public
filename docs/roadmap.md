# Web Watcher 阶段计划

日期：2026 年 10 月 6 日

## 初始化交付

初始化阶段交付需求、开源调研、架构建议、会话交接和 Git 仓库；当时没有应用代码，也没有安装、启用或修改系统网络任务。

截至 2026-10-11，M1 基础观测已实现，0.3.0 新增恢复事件存储、模拟状态测试、系统连接适配与切后验证，并整理为公开源码快照。M2 完整目标配置 / 网页历史仍待后续；M4 真实切网、后台凭据、锁屏及自动恢复耗时尚待实机验收。继续运行开发版，不推进正式打包。证据与接续事项以 [会话交接](HANDOFF.md) 为准。

## 后续里程碑

| 阶段 | 主要产物 | 必要验证 |
| --- | --- | --- |
| M1 可行性与应用起点 | 明确原生技术栈和最小工程；菜单栏、窗口；少量目标的只读 DNS、TCP、HTTPS 探测 | 实际路径符合配置；权限不足可解释；关闭窗口继续观察；正确区分 HTTP 错误与网络异常 |
| M2 连续监测与历史 | 多目标配置、调度、本地记录、故障与恢复时间线、基础趋势 | 超时和并发受控；探测不会持续叠加；数据保留与资源占用可测；断网不丢本地记录 |
| M3 恢复策略模拟 | 候选列表、策略状态、冷却、退避、人工暂停与模拟连接适配器 | 模拟上游断网、单站故障、代理故障、候选失败和恢复，确保不会错误切换或无限快速重试 |
| M4 真实网络恢复 | macOS 连接适配、结果验证、最小必要的后台或权限机制 | 在明确授权与回退保障下验证后台、锁屏、凭据、网络恢复及远程会话重新连接 |
| M5 本机试用 | 可安装应用、启动与更新说明、已知限制、持续运行记录 | 初次至少记录 24 小时监测表现，再安排恢复测试；记录 CPU、内存、流量、存储和实际恢复耗时 |

M1 到 M3 可以在不改变当前联网配置的情况下逐步开发。M4 需要真实切网与故障注入，必须安排有恢复保障的维护窗口。前期验收通过不等于已经保证长期无人值守。

## 新会话优先事项

1. 阅读交接与本地环境记录，刷新本机、Git 和网络状态。
2. 根据用户本轮要求确定开发范围，核对需求中尚未确定的默认行为；已有明确开发授权时直接推进其范围内的实现。
3. 优先核验授权后 SSID、手动扫描、进程统计稳定性和持续资源占用；实现所需的源码调研再按需补充。
4. 明确第一轮验收，只建立足以验证该轮目标的工程和功能。

跨平台、全流量抓包、局域网设备发现、云端通知和自动切回主网络暂未纳入第一版必做范围；有新需求后再调整。
