## 当前阶段与授权

当前为 0.3.0 恢复功能开发版，已补齐故障记录、恢复判断、系统连接适配与验证。本轮整理公开源码并进行隐私检查，仍采用开发版试运行，不做正式安装包。

自动恢复初始关闭；此前主、备用只是候选标记，现在已有实际连接流程。当前开发验证没有执行真实切网、修改 DNS / 代理、安装后台组件、故障注入或登录启动配置。真实切网、后台凭据及断网恢复仍待维护窗口验收；开启恢复开关后才会在异常时执行实际请求。定位授权仍由用户通过系统支持的接口处理。

公开仓库：[Doubixilin/web-watcher-public](https://github.com/Doubixilin/web-watcher-public)，默认分支 `main`。公开历史从经过隐私检查的 0.3.0 源码快照开始；不上传此前的开发历史、本机配置、原始日志或网络标识。接手时刷新 Git 状态与进程，不覆盖其他会话修改；后续公开交付继续核查文件及推送分支的完整历史。

## 本轮问题与恢复策略

0.2.0 只标记主、备用候选，没有连接适配器，不能执行切网。0.3.0 增加独立恢复判断和实际连接流程，覆盖无线断开与仍关联但出口不可达的场景。原始故障根因未确定，模拟测试不能替代真实恢复验收。

- CoreWLAN 订阅链路、SSID、Wi-Fi 电源事件，并每 2 秒复核状态。通过 SystemConfiguration 的链路状态结合 CoreWLAN 协议与电源信息识别关联 / 断开 / 关闭 / 未知；SSID 不可读不当作断线。持续断开约 3–6 秒后允许恢复；启动、休眠唤醒及手动变更会另外等待。关联后 15 秒无有效地址也可触发恢复。
- Wi-Fi 仍关联且有地址时，恢复判断独立于网站 30 秒调度：每 10 秒并行探测 3 个数字 IP 的 TCP 53，要求 Wi-Fi 接口类型，成功时核对本地地址确实属于所读无线接口。只有 3 个目标连续 2 轮全失败才尝试候选；未知结果中断连续失败。一个成功即可阻止自动切换。此证据表示疑似无线路径不可达，不等同确定设备上游根因，也不是 DNS 解析测试或 ICMP 丢包。
- 目标为阿里、腾讯与 Cloudflare 公共 DNS 的 TCP 53 服务，不发 DNS 查询、绕过权限、修改代理或读取密码。使用目标实际提供的服务端口，成功时核对本地接口；不能把目标未开放其他端口解释为出口故障。
- 只尝试用户配置且系统已保存的候选，按备用列表顺序，再考虑主网络；健康时不会自动切回主网络。切换前复核现有连接，若已有直连目标恢复则保持。调用系统 `networksetup -setairportnetwork`，不传密码、不提权；15 秒超时及退出清理。是否能无弹窗使用系统已有凭据仍需实机切换验收，不能从工具退出码推断。
- 请求后核对实际 SSID、接口、关联和地址，等待配置，再验证至少 2 个无线 TCP 目标；另测系统默认路径 HTTPS，HTTP 4xx / 5xx 仍算服务器可达。若无线出口可达而网站路径失败，保持该连接并提示检查代理 / 网站路径。远程控制会话是否恢复须另验。
- 候选失败继续下一个，最后尝试原网络回退；全失败等待 60 秒再评估。手动变更网络后等待 60 秒，成功恢复后冷却 120 秒。关闭开关、暂停监测、休眠或变更候选会取消后续请求；系统已受理的连接无法保证撤销，仍须观察实际状态。用户关闭 Wi-Fi 时不自动打开。
- “Wi-Fi 与候选”提供“连接并验证”按钮，属于真实切网；仅配置候选且系统已保存、授权有效时可用。可在开启无人值守恢复前验证两条网络及回退。
- `Application Support/WebWatcher/recovery-events.json` 原子保存最近 500 条事件，目录 / 文件权限为 0700 / 0600；记录观测时间、无线状态、信号、候选、TCP 汇总与验证结果，无凭据。读取 / 保存错误会阻止恢复并保留旧文件。退出、休眠及采样间隔记作观测间隔，不推断期间断网。网页完整探测历史仍未持久化。

## 当前实现

- Swift Package，SwiftUI / Swift Charts 窗口、AppKit 菜单栏，无第三方运行依赖或外部代码复制。
- 网站探测仍为百度 DNS、腾讯 TCP 443、百度与腾讯 HTTPS HEAD。单项 5 秒超时，轮次完成后等待 30 秒；串行执行、取消不发布半轮结果。HTTP 不跳转，预期 200–399，4xx / 5xx 与出口断网分开。
- 网站路径仍是系统默认路径。记录连接地址、映射接口、HTTP 代理标记和系统网络环境；没有已验证的物理直连或指定代理模式。
- CoreWLAN 读取 Wi-Fi 名称、RSSI、噪声、信噪比、当前协议 / 代际、频段、信道、宽度和发送协商速率。SSID 未获授权时显示未知，不使用历史名称代替当前连接；仅经系统支持的权限接口读取。
- `TelemetrySession` 约每秒读取物理接口的 64 位收发计数器，Wi-Fi / 接口详情约 10 秒刷新。按实际单调时间差计算 B/s，自动排除回环与隧道；首次、接口变化、计数器回退或超过 10 秒的间隔重建基线。
- 总览展示真实上下行与探测总耗时图。流量最近 180 个点、探测最近 480 个点仍只保留在内存。恢复事件已持久化；没有 ICMP、完整探测历史、请求失败率统计或公网测速。
- 主 / 备用候选、恢复开关、流量接口、菜单栏显示模式保存在本机 UserDefaults。候选列表区分已保存、手动候选与附近扫描；扫描本身不执行连接，实际连接入口与自动策略见上文。
- 进程页按需运行 `nettop -P -L 2 -n -x -J bytes_in,bytes_out`。独立读取两个样本后取最新累计计数，以有效采样的实际时间差计算进程速率；间隔超过 15 秒、计数回退或进程变化则重建基线。3 秒命令超时、1 MiB 输出上限、持续排空两条管道、TERM 后必要时 KILL。失败清除界面旧值，连续三次失败暂停；离开该页或关闭窗口停止，退出清理本应用子进程。
- 进程统计属于试验性功能，开发验证出现多次超时，尚未通过稳定性验收。软件名称只使用系统可识别的归属，否则展示原进程名；不猜测共享辅助进程的归属，不与网卡总量相加。
- 菜单栏可选择仅图标、下载、上传或上下行速率，并展示恢复状态。暂停网站监测同时暂停自动恢复，网卡采样和无线状态记录继续；关闭窗口保留监测、恢复与记录。

## 运行与验证

推荐运行 [开发脚本](../scripts/run-dev.sh)，使用固定应用身份在 `.build/Development/Web Watcher.app` 运行调试版，支持系统定位授权。这只是最小开发容器，不是正式分发包，未安装到 Applications。启动说明见 [README](../README.md)。

本机为 macOS 26.6.2、Swift 6.4、Apple Silicon；工程最低部署目标 macOS 14，未验证其他系统版本。开发版由系统启动，关闭终端不影响该实例。

已完成：

- `swift test`：45 项 XCTest 通过。保留原有 28 项，新增 17 项恢复测试：断线去抖、连续全失败与未知状态、手动变更 / 冷却、采样间隔、保存候选筛选、实际连接请求与验证分离、候选失败回退、停止时取消后续请求、代理路径失败不丢弃可达出口、手动连接、长时间切换不缩短成功冷却及日志重载 / 保留 / 权限 / 损坏保护。连接适配使用模拟对象，没有故障注入或真实切网。
- 实际 Wi-Fi 指标、物理网卡流量可读。这不能证明公网带宽或远程会话健康；正式 SSID 受定位授权限制。
- 有限进程采样取得过有效速率，也出现零输出超时。界面验证了首次未知、超时提示、连续失败暂停和手动重试，稳定显示进程速率仍待进一步核验。
